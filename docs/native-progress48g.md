# Checkpoint 48G: native collision data and terrain response

The native PC game goal remains active. This checkpoint supplies collision data and original physics behavior needed for driving; it does not establish a connected vehicle, full race, native gameplay FPS or Xbox execution.

## Native implementation

The built-in ISO/extracted-directory converter now creates versioned `RRCOL001` collision objects. It retains original vertices, optional vertex normals, AABB trees, face indices/planes, local transforms and complete source bytes. Typed records have explicit little-endian fields and native integer indices. Runtime parsing validates counts, references, cycles, source offsets and reversible provenance without invoking the original COL decoder. Existing geometry, textures, materials and worlds keep their object versions and bytes.

The optional `--world-collision` inspection path loads original static geometry and collision trees together under one cache read lock. TA has 318 static entries, 37 resolved collision instances, 36 unique retained collision assets and 281 absent optional original COL members. It preserves source-instance identity and composes the authored COL local transform with the distinct collision placement matrix. It never substitutes visible triangles or an invented floor. Authored separate collision lists/type/COL overrides are explicitly unsupported by this initial world loader; present but damaged/unconverted collision members are errors.

Original `0x1B1A30` terrain-following response is portable C++17: attachment/detachment, normal-force removal, height correction, velocity projection, reverse restrictions and scene alignment. The original no-time-argument behavior and stale cached local velocity are preserved. Surface-query results remain explicit inputs. This function cannot replace collision traversal, material filtering or SpringCollisionModel impulses/friction. The pre-query boundary must clear the per-substep largest velocity change; other recorded terrain histories persist. See [contact recovery](vehicle-contact48g.md).

Original quaternion/matrix conversions, quaternion-to-cached-angle extraction and the rational two-argument angle approximation are also portable native code. Strict binary32 operation order, scalar-first quaternion storage, largest-component ties and signed-axis behavior are retained. Repeated matrix round trips are tested because the original body wrapper reads orientation back from the scene. Full wrapper/callback scheduling is still outstanding.

## Verification and preserved discoveries

Final build: `evidence/nativePc48G-build-20261003-155827-581`, all 13 CTests passed on both architectures, including 88,316 collision checks each. Final end-to-end runs are `import48G-x64-2e_vsei8` and `import48G-x86-2ca15t6w` (seven native invocations each). The complete 103-container conversion in `importFull48G-gu9agzaq` passed: 17,799 accepted members, including 2,272 collision members; 16,329 remain explicitly unsupported. All 20,774 preceding archived cache object files remained byte-identical. The nine degenerate-plane assets are part of the unsupported set, not its entire collision subset. The parent verification is `evidence/native48G-parent/audit.json`.

All thirteen native CTests passed on both x64 and x86 before complete-disc validation. Orientation has 398,925 checks covering four quaternion selections, twelve angle branches and repeated round trips. Terrain has 241,921 checks, 5,900 complete original-word calls, twelve branch gates and four host rounding modes. Collision decoding compares every TA record against independently recovered original source data. Final build/audit paths and counts are recorded in the adjacent output checkpoint and manifest.

The original TA subset contains 38 COL members with 10,199 vertices, 14,548 internal nodes and 14,586 faces. Two animation members share source bytes, producing 37 distinct cache objects. Both architecture import tests check cancellation/resume, old-object preservation, byte-identical native fixtures, reuse, runtime rejection of corrupt collision data, repair and metadata repair. The actual combined native track load retains collision data and produces the identical preceding visual capture.

The first orientation test exposed an inherited test-only SQRT operand bug: the decoder used Fs instead of the EE's Ft. Every earlier executed square-root word used equal Fs/Ft values; the new matrix helper did not. The new oracle is corrected with supplied PCSX2/original-code evidence. Frozen preceding files remain intact. A terrain detachment mismatch exposed a native branch error and was corrected against original instructions. Integration additionally caught a missing collision dispatch in final cache verification and a test assumption that confused source-member count with unique object count. Failed logs remain recoverable.

Complete-disc validation identified authored non-finite face planes in MC `geometry\colmountd.col`. An audit of all 2,505 COL occurrences found nine assets with 54 such faces, all with coincident vertices. The exact authored pattern is D `0x7FC00000`, normal XYZ `0xFFC00000`; other floating-point fields are finite. The Cars plane builder divides the zero-length cross product by its length, consistent with this pattern. Only this exact pattern with coincident original vertices is classified as the named unsupported `col.degenerate_plane` variant, after structural validation. No face is deleted or repaired. Other non-finite patterns and malformed data remain errors. The output manifest records the final complete-disc result.

## Remaining work

Recover original query shape, tree traversal, hit selection and object flags; then connect terrain response, spring/impulse/friction and second-body interaction to the original whole-body scene update. Close physical action mapping, real timestep/cached-speed scheduling and before/after whole-substep evidence. Native collision assets preserve source-precision normals; the original loader's packed-normal query behavior is not yet reproduced.

Original material programs, sky, lighting, alpha/fog, visibility and animation remain unfinished, along with AI, camera, audio and progression. Final acceptance remains sustained 60 presented FPS at 1280x720 at correct simulation speed in representative complete races. Current captures are static offscreen readbacks, not that benchmark. Reported retained collision payload excludes allocator overhead and is not an Xbox memory or performance claim.
