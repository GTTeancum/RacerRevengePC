# In progress — GPU vertex path for opponent pods (design, Nov 7)

Goal: Xbox-style CPU/GPU split. CPU keeps per-part work only (scene palette /
bone matrices from buildVehicleDraw50CM stage 0, selected light rows, specular
camera coefficients); a vertex shader does per-vertex position, diffuse source
colour, map-2 UV and world normal. Removes the per-vertex CPU loops (~3.7 ms per
frame for 7 opponents) and the per-frame racer VBO/normal/UV uploads (bank reuse
without glFinish likely forces driver copies inside backend_transaction).
Scope v1: opponents only, single-sample fixed-blend route, components without
singleDiffuse fog. Player, AA coverage, RR_EXACT_PS2_SPECULAR and single-diffuse
bodies keep the CPU path.
Pieces: (1) cold per-archetype static skin VBO/VAO: local position, bone index,
compressed normal, local normal, uv, template colour; (2) per-frame submission
fields: bone matrices, scaled light directions (direction rows * normalQ), colour
rows, map-2 coefficients; (3) shader skin mode: world = rows(bone) * local;
amount_l = max(dot(scaledDir_l, bone3x3 * n), 0); rgba = clamp(round(ambient +
sum colorRow_l * amount_l), 0, 255) for selected materials else template;
uv2 = 0.5 * dot(cam, n) + 0.5; normal via bone cofactor; (4) shadow from cold
per-bone opaque-span moments (exact covariance) and per-bone local AABB
corners (conservative extremes); (5) validation of bones instead of vertices.
Validation rule found: selected light colour rows force lighting alpha = 64.

## Why this optimization is next

Build66's last recorded interval had 305 simulation steps:

- Scheduled total: 1,576,395,300 ns (~5.17 ms/step).
- Racer physics: 848,543,600 ns (~2.78 ms/step for all eight racers).
- Racer contacts: 363,650,200 ns (~1.19 ms/step).
- Racer children: 295,282,200 ns (~0.97 ms/step).
- Race sampling/presentation: about0.35 ms/step each.

These are nested scopes; do not sum children with their parents. Existing
contact adaptation makes three whole-fleet passes using full Bank::visit:
gather, verify and commit. Each nonzero racer visit copies four 313745-byte
snapshots. Eight racers therefore copy about26.35 MB per contact step, even when
there is no collision. The proposed accessor targets that transport without
changing the actual collision calculations or dropping pair checks.

`observeOriginalAiFleet` and dynamic peer projections already use scalar
Bank reads and are cheap; do not mistake those for the expensive full visits.
Presentation has additional full visits, but contacts are the larger target.
