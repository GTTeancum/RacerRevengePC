## Lifetime and cleanup

The existing Bank pin strongly retains the runtime bridge. The bridge now owns its private CameraBinding, whose Session borrows that Bank and does not retain it. CameraBinding strongly retains the SAME aggregate lighting and manager objects. Source/candidate/Storage/Follow owners already remain under the bridge. This creates no Bank cycle. Session is declared after its camera backing, so it is destroyed first.

The existing private Bank destruction check now additionally requires actual Session.closed_, even if preparation failed before Follow was attempted. It reads only retained bridge/Session state after Bank span/snapshot destruction, never dereferences the dead Bank. CameraBinding destruction also rejects an unclosed real Session. No synthetic drained or camera-retired bool exists.

close invokes actual Session::close under the still-live idle same Bank, including real model/Entity release, Follow bank0 retirement and camera visibility removal. Only actual closed_ permits destroying the Session and dropping private light/pool borrows. Failure retains all owners for retry. Abandon invokes the existing abandonAndCloseSpatial; as in the existing caller, actual pending fade cancel/retire must occur first. The wrapper neither certifies nor simulates a renderer drain. Cleanup remains callable after aggregate terminal failure.

Aggregate close continues rejecting a live Bank pin. Correct sequence: source camera cleanup while Bank/display/renderer/model arena are live; actual per-slot query detach; genuine Bank destruction; checked aggregate close, including private particle manager and source backing. Wreck pointers/snapshots are not cleared or retired by this patch. Prepared wreck borrowers can independently prevent final aggregate close.

## Current integration boundary
