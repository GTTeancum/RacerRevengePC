## Ownership and ordering

The two unique_ptr allocations remain the only raw backing owners. Semantic child and data identities now use distinct immutable per-Config role tokens with epochs1 and2, issued once in this nonmovable Config lifetime. Tokens cannot be resurrected by host malloc address reuse. They are not EE addresses, do not expose native pointers, and cannot be reused for a future section allocation epoch. The first allocation publishes the table role; Wake observes that same role and the same data role. No raw backing or role borrow escapes the private Config. The completed getters own copied scratch/results, not borrowed spans.

After explicit admission:

1. A new current reentrancy check is recorded as dataAdmissionReent. This is a native gate, not a replay or alteration of the earlier source freeReent capture. Unknown or unsupported identity leaves both allocations and all logical fields intact.
2. The exact native data owner is reset first. dataRetired records that effect. The table owner, semantic child24, count20, name and all historical first-selection records remain intact.
3. The table-call correspondence gets its own current reentrancy check, recorded as tableAdmissionReent. Refusal preserves the data-retired/table-live state and keeps child24/count20 unchanged. No rollback or fabricated original return occurs.
4. The exact native table owner is reset. Only then the native projection sets count20=0 and child24=NULL, in the original157FC0/157FC4 order. A separate adaptedResumePC becomes157FE8. No name copy, replacement allocation, read, seek or new selection occurs.

## History, partial states and cleanup

Original allocation requests, return-side backing receipts, counts, name, query, seek/read histories, rows, pointer offsets and all getter results are retained. The sidecars are immutable history after retirement, not live guest storage. Float/integer/shader historical row bounds use their originating sectionCounted_ rather than the subsequently cleared current selected20. The shared field-lookup entry rejects native-retirement attempts before changing its source PC, reading a row or mutating scratch.

Section and Config preflights distinguish historical successful allocation from current live native ownership. Wake checks stable role identity rather than comparing or dereferencing a freed host address. Native retirement preflight admits exactly the unattempted, first-native-gate refusal, data-retired/table-gate refusal and fully retired states produced by the entry. It keeps optional false/zero receipts engaged correctly and never requires later process reentrancy to equal a historical gate capture.

Existing native Config withdrawal still releases its file/provider custody only after preflight. It does not become an original destructor or free receipt. Already-reset native owners are NULL, so later native destruction cannot free them twice; a table retained after a partial refusal still has exactly one native owner. Sidecar history is retained until ordinary Config destruction.

Resuming Wake loading requires a separately reviewed adapted path with new per-section epochs, own scratch/read/allocation histories, current-vs-historical ownership, exact name-tail effects, and explicit continuation tagging. The authentic NULL-old-child path remains a separate potential source-backed continuation. Neither is enabled here.
