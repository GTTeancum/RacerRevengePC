The roles are semantic identity tokens, not EE addresses. They are distinct from the older General Information roles1/2 and the earlier retirement occurrence.

## Historical versus live custody

Wake table/data allocation receipts, roles3/4, stored rows, offsets, pointer-zero identity, count, source read history and getter result copies remain historical metadata. Only the two raw malloc payloads retire. Retained metadata is not a live source memory alias and is not exported. The completed Wake getter scope cannot restart and consume retired rows. No new getter or replacement section role is added here.

Current-section accessors now reflect the native count/child clears, while Wake-load and new-selection preflights explicitly separate historical successful allocations from current payload ownership. Existing General Information and Wake history stays valid. The selection result's currentWakeRetained flag now requires both live payloads as well as current count/child identity, so a partial or complete retirement cannot report retained live Wake data.

Native withdrawal still validates the full historical/current state before releasing stream custody and revoking array views. It can occur after either native gate stop or completed retirement. Owner destruction later releases any still-live native payload and retained metadata through the existing RAII owners, once; it does not perform original free/close/destructor execution or erase completed history. There are no new exported pointers, allocations or asynchronous operations.

## Limits and next boundary

Missing selection remains its accepted separate path with current Wake retained for the next filename getter; this retirement API cannot affect it. On the found path, a future native-adapted loading packet must use fresh roles and its own two-pass transport and copy history. No current code claims that loading or its return. This adapter does not reproduce the original allocator's global availability, pointer arithmetic, headers, free lists, coalescing or any exceptional behavior.

No process-global header edit is made. The inherited unpublished vectors/section checkpoint still requires its narrow reviewed rebase, preserving vector-owner changes if it is applied first. No publication or broad overlay is authorized.
