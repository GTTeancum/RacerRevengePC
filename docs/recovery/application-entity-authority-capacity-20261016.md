# Application Entity authority cold capacity

The fixed64-entry native Application membership bound cannot describe genuine
RA collision ownership (178 loaded static collisions plus actual parents and
other owners).64 is a native implementation limit, not an original source rule.

Keep the existing allocation-free64-entry initial storage and the unrelated
public wreck-domain64 limit. A private `reserveAdditional` cold operation grows
only the Application registry and its matching traversal scratch. It checks
32-bit original count overflow and every native vector maximum, allocates all
three replacement arrays before mutation, then swaps them together. Allocation
failure preserves all old entries, captured identities, count and scratch.
Original Entity objects never move. Only private pointer/identity backing moves.
The actual ten-zone3CC owner now calls this before any counted constructor.
Future static collision admission must reserve its actual source-derived extent
before construction, rather than expanding under a live traversal.

Application's private synchronous View supplies its matching visit scratch
through ADL; `forest` zeroes exactly count bytes and uses the same cycle/parent/
sibling validation as before. Generic wreck domains retain the stack64 scratch
and reject larger extents. The hidden Application domain validates scratch,
entry and pointer extents before traversal. No pointer snapshot or View escapes,
no callback runs during these operations, and no runtime allocation is added to
attach/detach. Initial Application construction remains noexcept/allocation-free.

This change grants no enrollment by itself, changes no captured session/key,
and completes no missing source Entity constructor, parent callback or dispatch.
Existing raw Entity lifetimes and explicit owner retirement remain required.
Static review only; no builds/tests/syntax checks or execution probes.
