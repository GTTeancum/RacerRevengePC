# Bounded native FireP0t completed-publication stamps

Base: 19b440b. Isolated source-only candidate. No tests, compilation, syntax checks, conversion or gameplay execution. No startup activation.

## Actual evidence and owner

The existing source visual owner retains four authenticated worldInstance identities, zone1 ordinals366..369, exact SCB matrices, source geometry/material facets and the private image/renderer publication leases. This candidate adds stamps belonging **only to that bounded native publication**. They are not the retail shared scene stamp, a fabricated SoulTree parent, an installed emitter attachment74 or emission readiness.

`VehicleWindowGl50DS::Storage::acceptCompletedTrackVisibility` already runs only after genuine completed gameplay submission: checked `glFinish` in explicit finish, or checked completion followed by successful real swap/headless completion in the display path. Menu/fade targets and failed completion do not produce a new generation. The new code consumes the four actual stored submitted bits inside that same acceptance boundary. Cold admission already proved exact source-order span0..3 ranges and actual source ownership.

The private owner update requires the exact current renderer, private publication serial and strictly consecutive internally produced completed generation. No public caller can supply bits or a generation. Recording occurs for every accepted completion, even if no caller asks for a receipt; an omitted capture cannot erase earlier submitted history. The last-submitted stamp changes only for an actual issued draw. These stamps do not establish pixel visibility.

## Capture and use

- `renderer.completedRaStaticFire(receipt, diagnostic)` mints a typed `ra_static_fire_visual50LA::CompletedDrawReceipt`.
- It calls the existing completedTrackSpanVisibility boundary with private indices0..3 and private output bytes, revalidates current native texture/canonical maps, and verifies the stored generation and all four bits.
- The receipt strongly retains the actual source owner and privately stores its current publication serial and completed generation. Its default state is invalid. Copying it cannot forge or renew it.
- `owner.nativeAttachment(receipt, ordinal, out)` validates exact owner identity, both live private publications, current serial/generation, nonclosed state and current canonical map. It copies the retained worldInstance, zone, ordinal, actual world matrix, bounded-publication stamp, last-submitted stamp and actual latest submission bit.
- The returned numeric struct is an observation. No API here accepts it as authoritative source state or particle completion.

The current stamp is the low16 bits of the actual renderer-owned completed generation. Last-submitted stamps retain the most recent real issued draw, with uint16 wrap represented honestly; the explicit submitted bit remains available and must not be replaced by assuming that stamp equality alone proves visibility. Native publication counters/stamps reset only when a new real renderer publication is acquired. No canonical source or emitter state is reset.

## Lifetime and stale evidence

Each renderer publication increments an owner-private uint64 serial before GL initialization; exhaustion rejects new publication. Same-address renderer close/recreate produces a new serial, so a prior receipt cannot revive. A receipt's strong source retention prevents source-owner address reuse while it survives.

Accepted cleanup invalidates completion evidence before any fallible GL retirement work. Incomplete cleanup still retains the source/image leases as before, but a saved receipt is already unusable. A wrong-thread or wrong-context close rejected before cleanup starts changes no publication state. Actual retirement clears the live renderer link. Image/source close then follows the earlier checked retirement order.

A later completed generation makes an older receipt stale. Overflow or an internal span/serial/continuity mismatch invalidates completion evidence rather than minting a receipt. The actual successful GPU completion may still stand as a renderer event; this optional source proof fails closed. Receipt queries allocate no new storage and do not draw, finish, mutate stamps, consume RNG or create managers.
