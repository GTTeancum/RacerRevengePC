## Native partial retirement and retry

The full original WaterObjectData destructor cannot be used as partial cleanup. After a positive child count has been read, resource+10 is still NULL and no child pointer array exists, while 2BA970 would iterate that count and dereference the array. This implementation neither invokes nor claims that source destructor or 104970 release.

The existing local Pool validator now checks descendant resource history and live ownership before the combined count floor and provider cleanup. It remains nonrecursive and still contributes exactly one Pool Entity. That validates the exact resource alias, constructor reference, known bytes and count-read effects before any Config withdrawal.

Cleanup preserves the existing order:

1. Preflight the Pool count, resource history/custody and exact file close/pin requirements.
2. Existing fallible Config abort, then World400/light withdrawal.
3. Cancel the exact file while its independent pin remains held; only after a successful close is that pin released.
4. Revoke the native Pool-local resource alias, discharge the one native-held constructor reference once and release only the 0x30 native backing.
5. Existing Pool argument revocation, canonical Entity authority/reference/count retirement and 0x1D0 storage release, followed by provider/array cleanup.

A file-close refusal leaves the resource and alias intact. A later Pool authority-retirement refusal leaves file closed and resource retired, with the Pool still counted and its private arguments restored. Retry validates those histories, skips completed file/resource retirement and never repeats the count read. Resource and file history survive storage retirement without dereferencing old roles. No source count is zeroed to ease cleanup, no source destructor/free/NULL receipt is fabricated, and no association is cleared.
