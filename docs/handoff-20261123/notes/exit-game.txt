What the player gets
--------------------
Main shows a sixth line "EXIT GAME" under the five original rows, in the same font, colour,
fade and selection arrows as those rows. Up/Down move into and out of it (it sits in the wrap
ring after the last row: ... OPTIONS -> GALLERY -> EXIT GAME -> TOURNAMENT ...), with the
original move sounds. Enter/Space/pad A on it opens a yes/no dialog that looks and animates
exactly like the game's own shared popup (dim, three orange strips, cross = Confirm, triangle =
Cancel); Enter/Space/A confirms, Escape/pad Y cancels (original sounds 1 / 5). After Confirm
the dialog closes with its normal animation and the game shuts down through the same path as
the window Close button.

Why it is not a real ui.dat row
-------------------------------
The original Main page (UIMAIN ui.dat page 1, Group 1) has exactly five controls; the port's
widget manager rejects any other count (applyMainWidgetPhase: groups[1].controls.size()!=5),
the 49-slot widget bank and navigation arrays are the original's own data, and Main's
destinations are hard-wired by slot (1E5E00 dispatch, slots 1..5). Adding a sixth control would
mean writing past proven bounds of original structures. So the row is a host-side addition
that is drawn by Main's own collector with Main's own materials and text code:
  - nothing is added to ui.dat, the widget bank, the navigation arrays, APP UI+47C or the
    shared 470/47C dialog owners;
  - the only touch on original state is the manager's own deselect/select command on an
    existing Group 1 control (the same command the original movement issues), so the
    original row stops looking selected while EXIT GAME is selected, and is reselected (or
    the original move runs) when the player leaves EXIT GAME.

The shared 47C dialog itself cannot be reused without header edits: its message text is
chosen from four cold-prepared variants (original_ui_controller_popup_geometry50kg.h,
textVariants_[4]) keyed by flags in original_ui_controller_popup50kg.h, and both headers sit
under ~30+ includers (original_ui_main_session50kg.h has 31 direct includers). Closest faithful
approach used instead: a HOST copy of the 47C state machine (the original
OriginalUiControllerPopup50KG start/input/update/render functions, run on a private state,
never on APP UI+47C), drawn with the 47C's own materials (dimpopup, overlay1popup,
venus14popup, icon_x_popup, icon_tri_popup) at the 47C's own layout constants (2055B0/2064C0:
message centred at 320,204; Confirm label 412,257 with cross at 380,247; Cancel label
232,257 with triangle at 200,247; strip UVs and colours), packet depth 16777214, same packet
order. The Confirm/Cancel labels are the original LOC 9 / LOC 10 strings (read from the 47C
popup's prepared texts); only the message "EXIT GAME?" and the row text "EXIT GAME" are
PC-native strings.

After a race (race-return frontend)
-----------------------------------
A race-return frontend builds a fresh Main session when the player backs out to Main; the row
is prepared again at that bind and the exit uses the same closeWindow(). The race-return close
itself was fixed in 47fd2d7 (shared dialogs 470/47C retire from the never-attached state); the
exit request is taken at the top of the loop, i.e. after a fully completed frame, the same point
a window Close is honoured. The race-return Garage first-frame rule is unaffected (exit only
comes from Main).
