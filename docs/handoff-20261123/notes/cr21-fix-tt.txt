so I made NO code change. The expectation in PLAN 5.3 run 3 and 5.5 ("common_race_start
reason=restart caller=1ABC0C" after the lap) cannot be met by the original's own rules.

Evidence (D:\Programming\GitHub\RacerRevengePC\work\scratch\dis_all.txt):
 - 1A7DA0..1A7DAC: the race update enters the end dispatch 1A7DD0 only when B4+58 bit0 is set.
 - 1AFA44..1AFA64: B4+58 bit0 = the return value of 1B0A70.
 - 1B0A70: when B4+58 bit5 is clear, it returns 1 only if every human row has +48 bit0 set
   (row = racer+C90, so +48 is CD8 bit0, "finished"), a retired human included.
 - CD8 bit0 is set only at 1B035C, inside 1B02F0. 1B02F0 returns at once when B4+58 bit5 is
   clear (1B02F0..1B02FC). A search of all byte stores to +0xCD8 and to row+0x48 finds no
   other writer of bit0.
 - B4+58 bit5 is written only by 1AF960(B4, a1), with a1 = (App2DC+11258 == 1)
   (1A7750..1A7758). So bit5 is clear in a Time Trial (11258 == 3).
 - The lap tail 1A2B80 (port: D:\Programming\GitHub\RacerRevengePC\.claude\worktrees\cr-main\src\game\lap_completion50gg.cpp:132-143)
   runs, for 11258 == 3, the per-lap 217940 / 217420 player reset and skips the last-lap
   22B760. 217940 (D40 virtual94, racer virtualA8 = 1A2B70 `jr ra`, +64/+68/+78) sets no
   finish bit. The TT lap count in 1125C is used only by the 3-lap race-record lookup
   (1A2CF0).
 - The port matches: manager flags58 = 0x46 (bit5 clear), finish_count54 = 0, player_cd8 = 0.
   The 1ABBC0 -> 1ABBE8 -> 1ABC0C branch of 1AB520 exists, but in a Time Trial nothing
   reaches 1A7DD0, so it is not reached by a lap.
What this means for the plan: a Time Trial runs lap after lap until Pause QUIT (row 10 ->
1BDAB4, item b). PLAN 5.3 run 3 / 5.5 should drop "TT finish restart 1ABC0C". The best lap
CB4 is still kept across restarts (216690 with 11258 == 3, Pause RESTART), and that can be
proven with a Pause RESTART instead.
Not proven: I read the disassembly only. The finish bit could have a writer this search
missed (for example a word store covering CD8, or a store through another base). That is
unlikely, because 1B0A70/1B02F0 tie "finished" to bit5 so directly.
