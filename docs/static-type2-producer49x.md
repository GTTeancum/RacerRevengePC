## Storage, errors and numeric limits

All production storage is native and caller-owned. No hot allocation, recursion, global mutable query scratch, guest CPU/device execution, locks or threads are introduced. Cold-validated views must remain immutable; edits require revalidation. Entire declared writable capacities, including unused tails, must be mutually disjoint and disjoint from nested inputs. Complete commits results even for a miss. Errors preserve all destinations/results; scratch may change. Stack/trace/pair/record shortage never truncates a successful query. Aggregate visit and candidate×ray bounds are checked for size_t overflow.

The retained reference model is round-to-nearest binary32 with separate operations and no FMA. It is an ordinary-finite-intermediate source model, not a universal checker or claim about all original floating exceptions/devices. The axes helper explicitly rejects unsupported positive-subnormal VU normalization. Opaque endpoint W payloads may still contain arbitrary bits.

The actual query maximum depths are6/5 and largest TA target depth33. Conservative DFS bounds are40/39 four-byte items. Pair payload is64 bytes plus20 bytes native metadata. Each query needs24/16 pair slots; logical record capacity remains caller-supplied. No capacity is inflated to avoid original saturation. Memory measurements are host ABI figures, not Xbox measurements.
