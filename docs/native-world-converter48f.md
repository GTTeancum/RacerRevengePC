# Native original world recovery 48F

48F ports the frozen `tools/assets/decode_world48e.py` labelled-block and world
semantics to portable C++17. The decoder retains every original block, field,
value, and offset, then recovers zones, portals, resource references, source
vectors, and placement matrices. It does not execute guest code, replay graphics
packets, infer placement, or implement visibility, collision, animation, or
lighting. A separate neutral cache format stores the recovered typed world.

## API and integration

`src/assets/import_world48f.h` exposes:

- `decodeParameters48F`: original BINARY1 labelled-block document to
  `ParameterDocument48F`, retaining exact `original_bytes` and every field.
- `encodeParameters48F`: reversible serialization preserving physical value
  order, which differs from sorted label-table order.
- `decodeWorld48F`: original SCB to `World48F`. `parameter_block` indexes link
  interpreted zones, portals, and instances to their complete original fields.
- `validateWorldSemantics48F`: reconciles typed semantics against the retained
  parsed fields, without reading the original BINARY/SCB layout.

All original decoding calls use `DecodeError48C`; decode calls accept optional
`DecodeHooks48C` and reduced caller limits. Outputs remain unchanged on failure
or cancellation. Successful calls clear earlier errors. Callbacks use the
existing synchronous nonthrowing/nonreentrant contract.

`src/assets/world_asset48f.h` exposes `encodeWorldAsset48F` and
`parseWorldAsset48F`, returning errors through `std::string`. The native asset
parser reads typed neutral records, rather than invoking an SCB decoder at
runtime. `max_world_asset_bytes48f` is 32 MiB. The parent owns cache metadata,
source hashes, resource resolution, runtime placement, and renderer integration.

`cmake/NativeWorld48F.cmake` is an include after the existing native decoder
target setup. It adds the two production sources and `racer_native_world_check`.
Production sources have no JSON or platform dependency. The test uses JSON and
Windows SHA256 to compare independently frozen evidence.

## Original format boundaries

The exact labelled BINARY1 subset is documented in `docs/world-scene48e.md`.
Original integers are little-endian uint32. The seven-byte `BINARY\0` magic,
version 1, sorted lowercase names, eight-byte block table, 43-byte field records,
NUL/string padding, contiguous physical coverage, and every source extent are
checked. The block's recorded size excludes its four-byte field count. String
values retain their physical order and printable ASCII text. Every accepted
document must reserialize byte-for-byte to its input.

Hard ceilings are 2 MiB/original file, 8,192 blocks, 1,024 fields/block, and
512 bytes per original string including NUL. World limits are 256 zones,
4,096 portals, 10,000 instances/zone, and 100,000 total instances. Caller limits
may only reduce these ceilings. Counts, extents, and original field coverage are
checked before dependent allocations. Cancellation is checked across parameter
blocks, zones, instances, and portals before output commit.

Decimal-vector grammar matches the frozen Python reference. Values first round
to binary64 and then binary32. Derived orientation uses ordered binary64 cross
products, squared lengths, `sqrt`, and divisions. The native implementation uses
locale-independent `from_chars`; a bounded decimal-magnitude check distinguishes
underflow from overflow when it reports out-of-range. Signed zero is preserved.
`evidence/importWorld48F/decimal-reference.json` contains nine independent cases
generated by the unchanged Python48E oracle, including a tiny decimal without
an exponent, negative-zero underflow, finite binary32 maximum, and overflow.

These operations preserve the frozen scalar reconstruction; they do not claim
bit-exact original VU reciprocal-square-root behavior. The original loader's
instance matrix replaces the saved PSG root transform. Consumers must use local
mesh vertices with this placement instead of multiplying an already flattened
root bind again. Frozen TA evidence includes 42 nonidentity roots for which that
distinction changes placement.

## Native RRWORLD1 schema

All integers are explicit little-endian uint32; all scalar vectors/matrices use
IEEE binary64 words serialized little endian. No pointers, JSON, guest register
state, or platform structures appear in this format. Strings are a uint32 byte
length followed by printable ASCII bytes without NUL, at most 511 bytes.

The 48-byte header contains:

| Offset | Value |
| ---: | --- |
| 0 | Eight bytes `RRWORLD1` |
| 8 | Asset version 1 |
| 12 | Exact complete native file length |
| 16 | Original parameter version |
| 20 | Original parameter header-table offset |
| 24 | Retained original byte count |
| 28 | Block count |
| 32 | Zone count |
| 36 | Portal count |
| 40 | Instance count |
| 44 | Scene-info block index |

Exact original bytes follow. Native block records then contain name, original
name offset, table-entry offset, block offset, size excluding count, and field
count. Each field stores name, value, entry offset, value offset, and original
value byte count. All uninterpreted blocks and fields remain present.

Each zone stores zone number, model count, and block index. Each portal stores
section name, block index, two connected zone numbers, and four binary64 xyz
vertices. Each instance stores section/geometry/collision names; zone, ordinal,
block index, source block offset; position/look/up vectors; a row-vector 4x4
matrix; and the original lighting flag as uint32 zero or one.

The cache validates all original provenance ranges and string bytes. It also
checks the retained original magic, version, counts, name lengths, block table,
field table offsets/lengths, and physical coverage against those typed records.
The raw bytes are provenance data, not the runtime decoder's input format.
Semantic validation compares declared counts, references, vectors, lighting
flags, portal connections/vertices, and exact recomputed placement matrices to
the retained source fields. Arbitrary affine matrices are rejected, even when
their translation and final row look plausible. Trailing native bytes, nonfinite
numbers, invalid references, and count/extent inconsistencies are rejected.

## Coverage and unsupported original variants

Parent-owned `evidence/worldImport48F/reference-index.json` contains all 36
original TRACKS SCB occurrences. Its independent frozen Python results accept
12 worlds: GA, GB, GC, MA, MB, RA, RC, SA, SC, TA, TB, and TC. Together they have
186 zones, 206 portals, and 15,340 authored instances. Native tests compare every
accepted field, vector, matrix, and original member SHA256; emitted native caches
must reparse and reserialize identically.

The other 24 occurrences are reported explicitly as unsupported:

- The 23 ending containers share SHA256
  `960de53dd95801db61181616465fad69347bb132b57be869ccc2d7312583e1a4`.
  They have a complete unzoned `staticmodels` / `modelN` schema with 142 models,
  rather than numzones/numportals and zoneN-modelM. Their known default-start
  vectors, model counts, headers, positions, and look vectors are validated
  before returning `world.flat_static_schema`. Missing fields in an ordinary
  zoned scene remain fatal; no default up-vector or lighting flag is invented.
- MC SHA256
  `26f5d637533ee9840e916e02d5cef7b06d68352f1b7e0b11a48bf050d73df51e`
  has repeated `colorrgb` and `type` labels in its environment block. Complete
  physical bounds and coverage are validated before reporting
  `parameter.duplicate_label`; no duplicate-value precedence is assumed.

The native accepted subset therefore stays aligned with frozen Python48E.
Unsupported variants do not become invented world data, and damaged bounds or
syntax do not become generic skips.

## Validation records

Tests include both frozen TA SCB and TOB byte roundtrips; all twelve world
references; original raw provenance; native encode/parse/encode identity;
boundary-sampled original/native truncations; altered table/count/string
records; malformed semantic values; cancellation and caller caps; an independent
analytical handedness/translation example; and corrupt affine bases, source
vectors, resource names, flags, and raw headers. The tests avoid exhaustive
large-file prefix scans.

Run the parent-built checker as:

```text
racer_native_world_check PROJECT_ROOT REPORT_JSON OUTPUT_FIXTURE_DIRECTORY
```

The optional output directory receives canonical `.rrworld` fixtures for the
parent to compare with built-in importer outputs. Tests write no frozen evidence.
Final architecture reports, exact source/build references, and the owned source/
evidence manifest are preserved under `evidence/importWorld48F/`.

The final x64 and x86 builds each pass **416,524 checks with zero failures**,
including all nine decimal fixtures. All twelve native `.rrworld` outputs are
byte-identical across architectures. Final build records are in
`evidence/nativePc48F-build-20261003-150459-931/`. These decoder/cache results do
not assert a playable race or a gameplay frame rate.

Report readback identified a test-only C++17 temporary-lifetime defect in the
first added decimal-fixture loop: the reported count remained 416,500, revealing
that the nine new cases had not run. The test now retains the JSON document for
the loop's lifetime and explicitly asserts nine fixtures. This correction
changes only test code; the production decoder/cache bytes and application
binaries remain unchanged. The earlier 416,500 results cover the original world
corpus but must not be cited as having exercised those decimal edge cases.
