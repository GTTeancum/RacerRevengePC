# TA and selected-rider Course races

This native route adds original-AI TA races and Course destinations TA/GA with
actual prepared Riders 2, 4, 10, 11, 12, 15, 19 and 20. All eight racing vehicles retain their
original AI owners. The one-human bits written by the real Course profile are
preserved; the native all-eight-AI driving policy is separate. The existing
ALL8 finish policy is unchanged.

## Course handoff and ownership

The source frontend still performs the genuine Course exit, queue9, profile
commit and renderer retirement. TA is course0/planet0/slot1; GA is
course8/planet1/slot4. Mode0, subtype1, three laps and eight entrants remain the
admitted Course configuration. Default-unlocked Rider UI selection is broader
than the currently owned race-resource domain.

An already loaded matching track/rider uses the existing activation boundary.
A changed track or rider publishes a typed cold-load request. Its catalog
authenticates the actual target RES and selected original roster/PHY/import
identities before admission; it does not declare GPU or gameplay owners ready.
The old session then closes its real renderer, audio, UI and world resources.
Only after `runSession50DU` returns and all local owners are destroyed does the
application recheck the actual committed profile and enter the selected cold
loader. Missing or invalid target resources fail there, without an alternative
track or pod. The same application RNG, selectors, clock, profile and camera
preferences survive. The existing gameplay-lighting lease is retired only
after real world destruction.

Riders4/10/11 are already members of the original eight-racer field. The cold
selection moves their complete existing entry into camera slot0 and retains
all eight distinct vehicles. Rider19 retains the existing authenticated
supplemental policy, replacing only POD01. Selecting another rider never
substitutes POD19.

## Native admission

The original Main application can begin with RR_TRACK=TA or explicitly admitted
GA. This Course route requires RR_ORIGINAL_AI_ALL_RACERS=1, RR_RACE_MODE=2 and
RR_START_MENU=0, plus the existing original UI, race, audio and prepared asset
inputs. GA retains RR_GA_ORIGINAL_AI_CANDIDATE=1 even when startup is TA. Original
CAM staging remains `work/native/project/disc/PODS/PODxx/PODxx.CAM`.

Source-positive scene cuts, TV finish/replay and retail roster/root parity
remain outside this implementation. MA/SA are now joined separately; see
`ma-sa-native-course-bindings-20261012.md` for their asset prerequisites. Existing native
world, audio, timing and presentation policies still apply. This patch adds no
translation units. It was reviewed as source only; no build, syntax probe,
decoder, game or test was run by its authors.

## TA camera visibility and Binder integration

TA reserves the same independent camera registration as GC and GA, allowing the
actual serial camera visibility lease. Its eight-racer Binder receives the real
application-clock publication even without a GC/GA animated-world collection.
Source ambient registration at 148F90..148FFC writes global ambient +50 on every
ambient before zone propagation; TA consequently retains the last numeric-order
ambient registration independently of selected-zone lighting. Authenticated TA
has no ambient flash authoring and uses the original/default fog fraction 1.
Course admission also requires the actual original camera path to be enabled.
These closures have been source-reviewed and integrated; no new software test
has run for this patch.
