# Native Main draw assembly (staged reconstruction)

This is new native C++ reconstruction, not recovered historical source. Files are staged only; the root coordinator owns integration. No build, syntax check, helper test, native parser/importer, game launch, guest execution, or emulator was run.

- An atomic cold owner constructs the actual shared49-slot UIMAIN manager and pins authenticated APPSTART/UIMAIN/UIFONTS/CONTPOP/OVERLAYS archives and the native video-mode lifetime.
- Four real CEL/PST font pairs retain source metrics and half-pixel glyph positioning. All37 Overlay_Text descriptors are prepared from the same manager, including hidden shared-bank pages. No page-control membership is treated as a widget parent or drawn twice.

- Live widget text colors, alpha, enable/visibility and source positions feed renderer quads; genuine empty/zero-area glyphs retain their source behavior. Draw never performs a hidden entity update or changes selection.
- Source Main background/arrow/Icon/text packet Z is retained on the640x448 source canvas. Positive fractional assigned depth is explicitly rejected until its arithmetic owner is established.
- Shared aperture rendering retains native source geometry and real `NoTexture` material, with original black RGB, alpha63 and depth1. It is neither a fabricated white texture nor an extra synthetic panel. Main aperture69/0.5 geometry remains the real aperture owner's responsibility.

### Bounded presentation-alpha and empty target proof

The accepted native Main graph samples only genuine read-only PST/ATM images, or no image. Every ScreenObject policy rejects destination-alpha testing/factors and unsupported render-target inputs. ParticleCode's separately admitted two states use source alpha, DATE0, and no destination-alpha consumer; its alpha test and fog are implemented in the native particle shader. No shared shadow/gleam/KO-font geometry is submitted by this closed Main graph. No subsequent pass samples the presentation target as a material atlas. Final presentation copies RGB with opaque presentation alpha. This is a bounded native graph proof, not source framebuffer-alpha emulation or a claim about every game screen.

### Actual texture-alpha admission correction

Independent source-data inspection found that the selected original atlases use full-byte palette alpha: most reach255 and mmbkg reaches203. The old one-map material guard `atlas alpha <=128` would therefore reject real Main resources. This stage removes that unsupported per-texture restriction without changing any pixels or scales. The companion native renderer change caches each exact CPU atlas's maximum alpha at cold bind and rejects a blended span before target writes unless `vertexAlpha * atlasMaximumAlpha <=16384`. Main ScreenObject packets use alpha63 and its fire packets are bounded to64, so the genuine full-byte textures satisfy the original modulation/blend coefficient range. The old128x128 subset remains valid. Neither a private alpha rewrite nor arbitrary GS factors above1 are silently approximated.

The independent asset-byte inventory is retained at `../ui-main-scene-reconstruction/cross-module-review/asset-admission-inventory.json`. It is data inspection evidence, not an executed native loader or renderer result. The integrated companion renderer records the exact maximum from its own immutable CPU bank before upload.
