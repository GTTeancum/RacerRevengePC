## Decision and scope

The approved host policy is immutable highest-resolution original base-image publication, already authenticated by the source image-bank owner. The original texture-address/palette-address/resident-mip packet fields are represented here by that actual native binding's original member, stored PST range, base mip, original image kind, dimensions and typed color interpretation. This is a bounded native semantic port, not a reconstruction of historical console allocation/residency or a claim of literal249BA0 byte parity under arbitrary device relocation.

The separate cold comparator remains unchanged except for private friendship to the new retained-state class. Its constructors, free function signatures and cold admission remain identical. This package extends the previously staged material-pass-equivalence package; its exact header preimage is included. New source files are absent from the active checkout.

## API

`OriginalUiMaterialBindingState50KG` is copyable for transactional staging and default-unsupported.

- `initialize(preparedColdKey, diagnostic)` initializes once, preserving the actual constructor fields. Reinitialization rejects.
- `recordDrainedBinding(const OriginalUiImageBank50KG&, combinedImageIndex, diagnostic)` records the actual resolved native base binding. It reads the combined owner's authenticated ScreenAssets internally and accepts no readiness Boolean, synthetic image token or caller-selected color policy.
- `compare(other)` returns the existing unsupported/notEquivalent/equivalent enum.
- `initialized()` and `bound()` expose state observations, not setters.

The binding method verifies actual published RGBA/dimensions against the same owner's full original decode, canonical source member/range, original revision/kind/mips and typed IPUM provenance. The image index is used only to resolve the actual bank image; its numeric value, GL name, CPU owner address and bank generation never determine equality. Indexed original palette alpha remains unchanged. Kind2 accepts only the existing authenticated RGB5/TEXA255/AEM1 policy and applies its source-proven TEXA replacement.

Failure preserves retained state. Disabled or zero-map passes reject a binding call. Zero-map state compares through the unchanged constructor key. Unique animation/group exclusions remain non-equivalence even for the same state object.

Passes whose geometry redirected into that leaf remain in their own earlier state. An empty/non-current-generation group does not bind. ## Cold versus bound proof

Original2476A0 constructs TEX0 from TCC and TFX only (247940..24795C). Those occupy bits34..36. Original249610 obtains the selected actual texture/mip, derives texture format, dimensions and palette semantics, and249780..2497F4 includes the nonzero width/height exponents at disjoint bits26..33 for the admitted power-of-two16..1024 images.249804..249814 preserves TCC/TFX while replacing the other fields.

Therefore a cold and a texture-bound pass are unequal under literal original packet comparison for this admitted image family, independently of memory addresses. The native retained-state cold/bound distinction captures that behavior directly, with no packet serialization or hardware model.

For two bound passes under the immutable native base policy, same canonical source/range/base-mip/kind/color semantics supplies the same binding state. Their remaining source constructor fields still must match. Original249818..24983C overwrites TEXA for the authenticated kind2 path, so the bound comparison replaces TA0/TA1/AEM with255/255/1 before comparing. Constructor differences in those overwritten fields must not spuriously prevent a merge; all other fields, including inactive blend/test/sampler fields, remain significant.

Historical source TEX0 also contained physical texture/palette addresses and selected residency. Equal original members alone do not prove equality of historical packets if those device allocations changed between draws. The native implementation deliberately does not recover those fields. Conversely, differing native GL object names or image-bank allocations do not make immutable native source bindings unequal.

## 19_1 /19_2 order consequence

The original Mat_Stbl places19_1 before19_2, with19c_1 between them; the following projection omits unrelated leaves only to show the material dependency.

Initially19_1/pass2 and19_2/pass2 are identical cold SpecularMapCompressed/specmap1 states. They are final passes of their respective materials, so the earlier specular group can redirect to the later specular group. Projected drain order is:

1.19_1 body
2.19_2 body
3.19_1 specular geometry, then19_2 specular geometry in actual leaf FIFO

Only the19_2/pass2 representative becomes bound from that shared leaf drain. The earlier19_1/pass2 remains cold. At the next real registry rebuild, cold versus bound prevents the merge. Projected order becomes:

1.19_1 body
2.19_1 specular
3.19_2 body
4.19_2 specular

After both separate groups actually drain, both can become bound. A later rebuild may merge them again under the same immutable native specmap binding and remaining-state equality. If a group has no geometry it remains unchanged, so do not toggle state based merely on the rebuild number.

Blindly reconstructing all keys as cold keeps the initial merge and incorrectly delays19_1 specular past19_2 body. Marking every alias bound likewise loses the split. This can change visible pixels: body2 can overwrite RGB/alpha/depth, and the original specular equation uses current destination alpha. Actual overlap, visibility and depth determine whether a given frame changes; source review does not establish a screenshot-level difference.

pod_wndw/pass2 has C=2/FIX255 and remains distinct from body specular C=1. pod_wndw/pass1 versuspass3 additionally retain their actual intervening pass barrier; binding history does not replace barrier enforcement.
